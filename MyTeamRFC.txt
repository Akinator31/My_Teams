Status of This Memo

   This document describes the MyTeams Protocol (MYTP), a custom
   application-layer protocol for the MyTeams collaborative communication
   system. It defines the command set, data formats, and exchange
   sequences used between the myteams_server and myteams_cli components.

   This document is produced in partial fulfillment of the Epitech
   G-NWP-400 project requirements.

1. Introduction

   The MyTeams Protocol (MYTP) is a line-based, text protocol for
   building a collaborative communication platform inspired by
   Microsoft Teams(r). It allows multiple clients to connect to a
   central server, manage user accounts, teams, channels, threads, and
   direct messages.

   The protocol is deliberately minimal: there is no TLS layer required
   by the project, and there is no password authentication. Identity is
   established by username alone.


------------------------------------------------------------------------

2. General Protocol Description

2.1 Transport Layer

   MYTP operates over TCP (Transmission Control Protocol). The server
   listens on a port specified at startup. The client connects to that
   port.

   The server MUST handle multiple simultaneous connections using a
   single-threaded, non-blocking, event-driven architecture.

   Usage:
      Server: ./myteams_server <port>
      Client: ./myteams_cli <ip> <port>

2.2 Message Format

   Every command sent by the client and every reply sent by the server
   is terminated by a Carriage Return and Line Feed sequence:

      <CRLF>  ::= \r\n

   Fields within a command are separated by a single space character
   <SP>.

   Command syntax summary:

      SIMPLE_COMMAND   ::= COMMAND [SP ARGS] CRLF
      CONTEXTUAL_COMMAND ::= COMMAND SP CONTEXT [SP ARGS] CRLF

   Where:
      COMMAND   = one of the command keywords defined in Section 5
      CONTEXT   = NONE | TEAM | CHANNEL | THREAD
      ARGS      = one or more quoted strings (see 2.3)

   The server replies with:

      REPLY ::= CODE SP MESSAGE CRLF

   Where:
      CODE    = 3-digit numeric reply code (see Section 6)
      MESSAGE = human-readable description (may include structured data)

2.3 String Syntax

   All string arguments in commands MUST be enclosed in double quotes:

      STRING ::= '"' CHARS '"'

   A command with a missing or malformed quote MUST be rejected by the
   server with reply code 400.

   Example of valid arguments:

      "my_team_name" "a short description"

2.4 Field Length Constraints

   The following maximum lengths apply to string fields:

      MAX_NAME_LENGTH        32   characters
      MAX_DESCRIPTION_LENGTH 255  characters
      MAX_BODY_LENGTH        512  characters

   The server MUST reject with code 400 any string exceeding its
   allowed maximum length.

3. Data Model

3.1 User

   A User is identified by a UUID generated by the server upon first
   login. A user has:

      uuid        : UUID (server-generated)
      username    : STRING (MAX_NAME_LENGTH)
      is_logged   : BOOLEAN (online/offline status)

3.2 Team

   A Team is a top-level organizational unit. It has:

      uuid        : UUID (server-generated)
      name        : STRING (MAX_NAME_LENGTH)
      description : STRING (MAX_DESCRIPTION_LENGTH)
      creator_uuid: UUID (user who created the team)

   Users may subscribe/unsubscribe to teams. Only subscribed users
   receive event notifications for a team.

3.3 Channel

   A Channel belongs to exactly one Team. It has:

      uuid        : UUID (server-generated)
      name        : STRING (MAX_NAME_LENGTH)
      description : STRING (MAX_DESCRIPTION_LENGTH)
      team_uuid   : UUID (parent team)

3.4 Thread

   A Thread belongs to exactly one Channel. It has:

      uuid         : UUID (server-generated)
      title        : STRING (MAX_NAME_LENGTH)
      message      : STRING (MAX_BODY_LENGTH)
      creator_uuid : UUID
      channel_uuid : UUID
      timestamp    : UNIX timestamp

3.5 Comment

   A Comment (reply) belongs to exactly one Thread. It has:

      uuid         : UUID (server-generated)
      body         : STRING (MAX_BODY_LENGTH)
      creator_uuid : UUID
      thread_uuid  : UUID
      timestamp    : UNIX timestamp

3.6 Message (Direct Message)

   A direct Message is exchanged between two users. It has:

      sender_uuid   : UUID
      receiver_uuid : UUID
      body          : STRING (MAX_BODY_LENGTH)
      timestamp     : UNIX timestamp


------------------------------------------------------------------------

4. Context Model

   Some commands (/create, /list, /info) are context-sensitive. The
   context is set by the /use command.

   Context states:

      NONE    : No team/channel/thread selected
      TEAM    : team_uuid is set, channel_uuid and thread_uuid are unset
      CHANNEL : team_uuid and channel_uuid are set, thread_uuid is unset
      THREAD  : team_uuid, channel_uuid, and thread_uuid are all set

   The context is per-client and maintained by the server for the
   duration of the session.

5. Command Reference (Client to Server)

   Commands are case-sensitive. All commands end with CRLF.

5.1 Authentication Commands

   LOGIN
   -----
   Syntax:  LOGIN "username" CRLF
   Purpose: Register or log in as the specified user. If the username
            does not exist, a new user is created and assigned a UUID.
            If the username already exists, the client is logged in as
            that user.
   Args:    username (MAX_NAME_LENGTH)

   LOGOUT
   ------
   Syntax:  LOGOUT CRLF
   Purpose: Disconnect the client from the server. The user's status
            is set to offline.
   Args:    (none)

5.2 User Commands

   USERS
   -----
   Syntax:  USERS CRLF
   Purpose: List all users registered on the server, including their
            UUID, username, and online status.
   Requires: Client must be logged in.

   USER
   ----
   Syntax:  USER "user_uuid" CRLF
   Purpose: Get details about a specific user identified by UUID.
   Requires: Client must be logged in.

5.3 Messaging Commands

   SEND
   ----
   Syntax:  SEND "user_uuid" "message_body" CRLF
   Purpose: Send a direct message to the specified user.
   Args:    user_uuid    : UUID of recipient
            message_body : STRING (MAX_BODY_LENGTH)
   Requires: Client must be logged in.

   MESSAGES
   --------
   Syntax:  MESSAGES "user_uuid" CRLF
   Purpose: List all direct messages exchanged between the logged-in
            user and the specified user.
   Args:    user_uuid : UUID of the other user
   Requires: Client must be logged in.

5.4 Team Commands

   SUBSCRIBE
   ---------
   Syntax:  SUBSCRIBE "team_uuid" CRLF
   Purpose: Subscribe to a team. The client will receive event
            notifications related to that team and its channels/threads.
   Requires: Client must be logged in.

   SUBSCRIBED
   ----------
   Syntax:  SUBSCRIBED ["team_uuid"] CRLF
   Purpose: Without argument: list all teams the logged-in user is
            subscribed to.
            With argument: list all users subscribed to the given team.
   Args:    team_uuid (optional)
   Requires: Client must be logged in.

   UNSUBSCRIBE
   -----------
   Syntax:  UNSUBSCRIBE "team_uuid" CRLF
   Purpose: Unsubscribe from a team. The client will no longer receive
            event notifications for that team.
   Requires: Client must be logged in.

   USE
   ---
   Syntax:  USE ["team_uuid"] ["channel_uuid"] ["thread_uuid"] CRLF
   Purpose: Set the command context. Arguments are optional:
              - USE                               -> context = NONE
              - USE "team_uuid"                   -> context = TEAM
              - USE "team_uuid" "channel_uuid"    -> context = CHANNEL
              - USE "t_uuid" "c_uuid" "th_uuid"   -> context = THREAD
   Requires: Client must be logged in.

5.5 Contextual Commands (/create, /list, /info)

   These commands behave differently depending on the active context
   (see Section 4). The context is set using the SET command and
   persists between command executions. By default, no context is
   set, so you need to define one using the /set command.
   Once the context is set, the client no longer needs to specify it
   when using context-related commands such as /create, /list, or
   /info. The context is stored on the server and is updated when
   the client uses the /use command.

   Syntax:

      CREATE ARGS CRLF
      LIST        CRLF
      INFO        CRLF

   Where CONTEXT is one of: NONE | TEAM | CHANNEL | THREAD

   CREATE
   ------
   Context NONE    : CREATE "team_name" "team_description" CRLF
                     -> Creates a new team.

   Context TEAM    : CREATE "channel_name" "channel_description" CRLF
                     -> Creates a new channel in the current team.
                     Requires: user must be subscribed to the team.

   Context CHANNEL : CREATE "thread_title" "thread_message" CRLF
                     -> Creates a new thread in the current channel.
                     Requires: user must be subscribed to the team.

   Context THREAD  : CREATE "comment_body" CRLF
                     -> Creates a reply in the current thread.
                     Requires: user must be subscribed to the team.

   LIST
   ----
   Context NONE    : LIST CRLF
                     -> Lists all existing teams.

   Context TEAM    : LIST CRLF
                     -> Lists all channels in the current team.
                     Requires: user must be subscribed to the team.

   Context CHANNEL : LIST CRLF
                     -> Lists all threads in the current channel.
                     Requires: user must be subscribed to the team.

   Context THREAD  : LIST CRLF
                     -> Lists all replies in the current thread.
                     Requires: user must be subscribed to the team.

   INFO
   ----
   Context NONE    : INFO CRLF
                     -> Displays the currently logged-in user's details.

   Context TEAM    : INFO CRLF
                     -> Displays details of the currently selected team.

   Context CHANNEL : INFO CRLF
                     -> Displays details of the currently selected channel.

   Context THREAD  : INFO CRLF
                     -> Displays details of the currently selected thread.

5.6 Miscellaneous Commands

   HELP
   ----
   Syntax:  HELP CRLF
   Purpose: Display the list of available commands and their usage.

6. Reply Codes (Server to Client)

   Server replies follow the format:

      CODE SP MESSAGE CRLF

   Where CODE is a 3-digit integer.

6.1 Success Codes (2xx)

   200 OK
       General success. Command was accepted and completed.

   201 Created
       A new resource (team, channel, thread, comment, user) was
       successfully created.

   210 User logged in
       The LOGIN command succeeded.

   211 User logged out
       The LOGOUT command succeeded.

   212 Users list
       Reply to USERS command. Followed by user data lines.

   213 User info
       Reply to USER command. Contains user details.

   214 Help message
       Reply to HELP. Contains the list of available commands.

   220 Message sent
       Reply to SEND. The direct message was delivered.

   221 Messages list
       Reply to MESSAGES. Followed by message data.

   230 Teams list
       Reply to LIST (context NONE). Followed by team data.

   231 Subscribed teams list
       Reply to SUBSCRIBED (no argument). Followed by team UUIDs.

   232 Subscribed users list
       Reply to SUBSCRIBED "team_uuid". Followed by user UUIDs.

   233 Channels list
       Reply to LIST (context TEAM). Followed by channel data.

   234 Threads list
       Reply to LIST (context CHANNEL). Followed by thread data.

   235 Replies list
       Reply to LIST (context THREAD). Followed by comment data.

   240 Team info
       Reply to INFO (context TEAM). Contains team details.

   241 Channel info
       Reply to INFO (context CHANNEL). Contains channel details.

   242 Thread info
       Reply to INFO (context THREAD). Contains thread details.

   250 Context set
       Reply to USE. The context has been updated successfully.

6.2 Informational Codes (1xx)

   100 Already subscribed
       The user is already subscribed to the requested team.
       (Informational, not an error.)

   101 Already logged in
       The user is already logged in from another session.

6.3 Error Codes (4xx)

   400 Bad request
       Malformed command, missing quotes, invalid argument count,
       or argument exceeds maximum length.

   401 Unauthorized
       The command requires the client to be logged in.

   403 Forbidden
       The client does not have permission for this action
       (e.g., creating a thread without being subscribed).

   404 Not found
       The requested resource (user, team, channel, thread) does not
       exist.

   409 Conflict
       Resource already exists (e.g., team name duplicate).

   410 Not subscribed
       The client is not subscribed to the requested team.

   411 No context
       A contextual command was issued but no context is set.

6.4 Server Error Codes (5xx)

   500 Internal server error
       An unexpected server-side error occurred.

   501 Not implemented
       The command is recognized but not yet implemented.

7. Command-Reply Sequences

   ->  denotes a message from client to server
   <-  denotes a reply from server to client


   7.1 Connection

      On new TCP connection:
         <- 200 SP Connected to MyTeams server CRLF

   7.2 Login

      -> LOGIN "alice" CRLF
      <- 210 SP User logged in. UUID: <uuid> CRLF

      (if user does not exist, it is created; same reply code)

   7.3 Logout

      -> LOGOUT CRLF
      <- 211 SP User logged out. CRLF

   7.4 List all users

      -> USERS CRLF
      <- 212 SP <user_uuid> <username> <is_logged> CRLF
         [one line per user]
      <- 200 SP End of users list. CRLF

   7.5 Get user info

      -> USER "user_uuid" CRLF
      <- 213 SP <uuid> <username> <is_logged> CRLF

      Error:
      <- 404 SP User not found. CRLF

   7.6 Send a direct message

      -> SEND "receiver_uuid" "Hello!" CRLF
      <- 220 SP Message sent. CRLF

      Errors:
      <- 404 SP User not found. CRLF
      <- 401 SP Unauthorized. CRLF

   7.7 List direct messages

      -> MESSAGES "user_uuid" CRLF
      <- 221 SP <sender_uuid> <timestamp> <body> CRLF
         [one line per message]
      <- 200 SP End of messages. CRLF
      
      Errors:
      <- 404 SP User not found. CRLF
      <- 401 SP Unauthorized. CRLF

   7.8 Subscribe to a team

      -> SUBSCRIBE "team_uuid" CRLF
      <- 200 SP Subscribed to team. CRLF

      Error:
      <- 404 SP Team not found. CRLF

   7.9 List subscribed teams

      -> SUBSCRIBED CRLF
      <- 231 SP <team_uuid> CRLF
         [one line per team]
      <- 200 SP End of subscribed teams. CRLF

   7.10 List users subscribed to a team

      -> SUBSCRIBED "team_uuid" CRLF
      <- 232 SP <user_uuid> CRLF
         [one line per user]
      <- 200 SP End of subscribed users. CRLF

   7.11 Unsubscribe from a team

      -> UNSUBSCRIBE "team_uuid" CRLF
      <- 200 SP Unsubscribed from team. CRLF

   7.12 Set context

      -> USE CRLF
      <- 250 SP Context set to NONE. CRLF

      -> USE "team_uuid" CRLF
      <- 250 SP Context set to TEAM. CRLF

      -> USE "team_uuid" "channel_uuid" CRLF
      <- 250 SP Context set to CHANNEL. CRLF

      -> USE "team_uuid" "channel_uuid" "thread_uuid" CRLF
      <- 250 SP Context set to THREAD. CRLF

      Error:
      <- 404 SP Resource not found. CRLF

   7.13 Create (contextual)

      Context NONE - create a team:
      -> CREATE <team_name> <team_description> CRLF
      <- 201 SP Team created. UUID: <uuid> CRLF

      Context TEAM - create a channel:
      -> CREATE <channel_name> <channel_description> CRLF
      <- 201 SP Channel created. UUID: <uuid> CRLF

      Context CHANNEL - create a thread:
      -> CREATE <thread_title> <thread_message> CRLF
      <- 201 SP Thread created. UUID: <uuid> CRLF

      Context THREAD - create a reply:
      -> CREATE <comment_body> CRLF
      <- 201 SP Comment created. UUID: <uuid> CRLF

      Errors:
      <- 400 SP Bad request (bad args, length exceeded, etc.) CRLF
      <- 401 SP Unauthorized. CRLF
      <- 403 SP Forbidden (not subscribed to team). CRLF
      <- 411 SP No context set. CRLF

   7.14 List (contextual)

      Context NONE:
      -> LIST NONE CRLF
      <- 230 SP <team_uuid> <name> <description> CRLF
         [one line per team]
      <- 200 SP End of teams list. CRLF

      Context TEAM:
      -> LIST TEAM CRLF
      <- 233 SP <channel_uuid> <name> <description> CRLF
         [one line per channel]
      <- 200 SP End of channels list. CRLF

      Context CHANNEL:
      -> LIST CHANNEL CRLF
      <- 234 SP <thread_uuid> <title> <creator_uuid> <timestamp> CRLF
         [one line per thread]
      <- 200 SP End of threads list. CRLF

      Context THREAD:
      -> LIST THREAD CRLF
      <- 235 SP <comment_uuid> <body> <creator_uuid> <timestamp> CRLF
         [one line per comment]
      <- 200 SP End of replies list. CRLF

   7.15 Info (contextual)

      Context NONE - logged-in user:
      -> INFO NONE CRLF
      <- 213 SP <uuid> <username> <is_logged> CRLF

      Context TEAM:
      -> INFO TEAM CRLF
      <- 240 SP <team_uuid> <name> <description> <creator_uuid> CRLF

      Context CHANNEL:
      -> INFO CHANNEL CRLF
      <- 241 SP <channel_uuid> <name> <description> <team_uuid> CRLF

      Context THREAD:
      -> INFO THREAD CRLF
      <- 242 SP <thread_uuid> <title> <message> <creator_uuid> <timestamp> CRLF

   7.16 Help

      -> HELP CRLF
      <- 214 SP Available commands: LOGIN LOGOUT USERS USER SEND ...
      <- 200 SP End of help. CRLF

8. Event Notifications (Server Push)

   The server may push unsolicited notifications to connected and
   subscribed clients when certain events occur. These use the prefix
   "EVENT" followed by a type identifier.

   Syntax:

      EVENT SP EVENT_TYPE SP DATA CRLF

   Event types:

      EVENT USER_LOGGED_IN    <user_uuid> <username>
         Sent to all logged-in clients when a user connects.

      EVENT USER_LOGGED_OUT   <user_uuid> <username>
         Sent to all logged-in clients when a user disconnects.

      EVENT TEAM_CREATED      <team_uuid> <name> <description> <creator_uuid>
         Sent to all logged-in clients when a new team is created.

      EVENT CHANNEL_CREATED   <channel_uuid> <name> <description> <team_uuid>
         Sent to all users subscribed to the relevant team.

      EVENT THREAD_CREATED    <thread_uuid> <title> <message> <creator_uuid> <channel_uuid>
         Sent to all users subscribed to the relevant team.

      EVENT REPLY_CREATED     <comment_uuid> <body> <creator_uuid> <thread_uuid>
         Sent to all users subscribed to the relevant team.

      EVENT MESSAGE_RECEIVED  <sender_uuid> <body>
         Sent to the recipient of a direct message.

      EVENT USER_SUBSCRIBED   <user_uuid> <team_uuid>
         Sent to all users subscribed to the relevant team.

      EVENT USER_UNSUBSCRIBED <user_uuid> <team_uuid>
         Sent to all users subscribed to the relevant team.

   Note: A user that is NOT subscribed to a team MUST NOT receive
   events related to that team.

   Note: A user that is NOT logged in MUST NOT receive any events.

9. Security Considerations

   9.1 Authentication

      No password is required. The username alone is used to identify
      a user. Clients SHOULD be aware that usernames are shared and
      that any client knowing a username can log in as that user.

   9.2 Authorization

      The server MUST enforce the following rules:

      - A client that has not issued a successful LOGIN command MUST NOT
        be able to execute any command other than LOGIN and HELP.

      - A client that is not subscribed to a team MUST NOT be able to
        create channels, threads, or replies within that team.

      - A client that is not subscribed to a team MUST NOT receive any
        event notifications originating from that team.

   9.3 Input Validation

      All string inputs MUST be validated against maximum length limits
      (see Section 2.4). Commands with missing, extra, or unquoted
      arguments MUST be rejected with reply code 400.

   9.4 Persistence

      On shutdown (e.g., SIGINT/Ctrl-C), the server MUST persist all
      state (users, teams, channels, threads, comments, direct messages,
      subscriptions) to disk. On startup, the server MUST reload this
      state if a save file exists.
